# Security Policy

## Reporting a vulnerability

Please do not open a public Issue containing exploit details, credentials,
personal data, or other information that would put users at risk.

Use GitHub's **Report a vulnerability** form in the repository's Security tab if
private vulnerability reporting is enabled. If that option is unavailable,
open a minimal public Issue stating that you need a private disclosure channel,
without including sensitive details. A maintainer will arrange an appropriate
private follow-up.

Include affected versions or commits, impact, reproduction conditions, and a
suggested mitigation when available. Maintainers will acknowledge the report,
investigate it, and coordinate disclosure based on severity and available
maintainer capacity. No response-time SLA is currently promised.

## Scope

Security issues include cross-user data exposure, lifecycle or persistence
invariant bypasses, unsafe provider data handling, credential exposure, and
dependency vulnerabilities with a demonstrated impact on Chronem. General bugs
and feature requests belong in the public issue tracker.

Never submit real personal memory data or working secrets in a report.
